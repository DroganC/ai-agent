# 前端技术方案（移动端消防安全训练平台）

**版本**：v1.0  
**日期**：2026-03-11  
**状态**：初稿（按需求约束：MobX + Less）

---

## 技术方案概述

基于需求文档，采用 React + Vite + MobX + Less 技术栈，实现移动端优先的消防安全训练 H5 平台。整体为「表现层 → 业务层 → 数据层」分层架构，路由采用 createBrowserRouter + 底部 Tab + 页面栈，状态通过 RootStore + Context 注入，样式由 Less 变量统一主题（主色 #0064ff）。接口与数据模型与后端约定一致，开发期可先 mock 跑通。

---

## 一、技术选型

| 类别       | 选择                    | 理由 |
|------------|-------------------------|------|
| 语言       | TypeScript              | 类型安全、与 React 生态一致，便于维护与重构 |
| 框架       | React 18                | 需求为 SPA，组件化与生态成熟 |
| 构建       | Vite                    | 开发体验好、构建快，与 React 官方推荐一致 |
| 路由       | React Router (createBrowserRouter) | 数据路由、集中配置，便于 Tab + 页面栈 |
| 状态管理   | MobX (mobx + mobx-react-lite) | 需求约定；适合多页面共享状态与派生数据 |
| 样式       | Less + CSS 变量         | 需求约定（不用 Tailwind）；主题变量统一、易扩展 |
| UI 组件    | antd-mobile             | 移动端组件齐全，与 Less 变量可联动 |
| 请求       | Axios + 统一封装        | 拦截器、超时、错误码统一处理 |
| 工程化     | ESLint + Prettier + TS strict | 代码规范与质量保障 |

## 二、架构设计

### 2.1 分层架构

- **表现层**：页面（pages）、通用组件（components）、路由与布局（app）。负责用户交互与界面渲染，不直接调接口。
- **业务层**：MobX stores（authStore、uiStore 等）。负责流程控制、状态与派生数据，调用 services 获取数据。
- **数据层**：services（API 封装、接口路径与入参）、mocks（开发期 mock）。对外提供稳定函数签名与数据转换。

### 2.2 模块划分

| 模块           | 职责                             | 依赖 |
|----------------|----------------------------------|------|
| app            | 路由、Tab 布局、全局壳（错误边界/初始化） | - |
| pages          | 页面级组件，与路由一一对应，组织布局与调用 store/service | stores, components, services |
| components     | 可复用 UI（Page、BottomTab、Button 等） | styles, types |
| stores         | MobX 状态、action、派生数据      | services, types |
| services       | HTTP 封装、接口定义、数据转换    | types |
| styles         | Less 变量、全局样式、主题        | - |
| types          | 领域模型与 API 类型              | - |
| utils          | rem 适配、错误信息等工具         | - |
| mocks          | 开发期 mock 数据与 handler       | - |

### 2.3 关键设计决策

| 决策点           | 选择                     | 理由 |
|------------------|--------------------------|------|
| 路由创建方式     | createBrowserRouter 集中配置 | 与需求/实现一致，便于维护与鉴权包裹 |
| 状态注入         | RootStore + Context + useStores | 避免 prop drilling，非 React 层可用 singleton |
| 样式主题         | variable.less + :root CSS 变量 | 主色 #0064ff 与 antd-mobile 联动，易扩展 |
| 移动端适配       | rem 动态根字号 + safe-area   | 与设计规范一致，适配多机型 |
| 接口联调前       | MSW mock                  | 无后端时可跑通列表/排行榜/个人页 |

## 三、信息架构与路由设计（移动端）

### 3.1 一级页面（底部 Tab）

- `/home`：首页（游戏列表）
- `/rank`：排行榜
- `/me`：个人主页（我的）

### 3.2 二级页面（页面栈，进入后隐藏 Tab）

- `/game/:gameId`：游戏首页（介绍页，含「开始游戏」）
- `/game/:gameId/play`：游戏内
- 其他：`/levels`、`/level/:id/prepare`、`/level/:id/play`、`/level/:id/settlement`、`/store`、`/store/orders`、`/learning` 等

### 3.3 路由创建方式（强制约束）

- 使用 `react-router-dom` 的 **`createBrowserRouter`** 在 `src/app/router.tsx` 统一创建路由表。
- 在 `src/main.tsx` 通过 `RouterProvider` 挂载；鉴权通过 `AuthGuard` 包裹子路由。

建议路由树（示例）：

```txt
/
  (AuthGuard)
    (TabLayout)
      home            -> Home
      rank            -> Leaderboard
      me              -> Profile
    game/:gameId      -> GameIntro
    game/:gameId/play -> GamePlay
    levels / level/* / store / learning ...
    *                 -> Navigate to /home
```

### 3.4 导航体验

- Tab 页固定底部，适配 iOS 安全区。
- 进入 `/game/*`、`/level/*` 等栈页后隐藏底部 Tab，使用顶部返回或系统返回。
- 支持 iOS 手势返回、Android 返回键与页面栈一致。

## 四、目录结构

```
src/
  app/
    router.tsx        # createBrowserRouter 路由表入口
    TabLayout.tsx     # 底部 Tab 壳 + <Outlet/>
    App.tsx           # 可选全局壳（错误边界/全局初始化）
  pages/
    index.ts          # 统一导出（可选）
    Home/
      index.tsx       # 页面入口
      components/     # 本页专属组件（如 LevelCard, LevelGroup）
    Profile/
      index.tsx
      components/     # 如 QuickEntryGrid
    Leaderboard/
      index.tsx
      components/     # 如 RankRow
    GameIntro/, GamePlay/, Levels/, LevelPrepare/, LevelPlay/, Settlement/,
    Store/, StoreOrders/, Learning/, LoginCallback/, Hall/
    # 每页一目录，入口为 index.tsx，可含 components 子目录
  components/
    common/           # Page, Button, BottomTab, Loading, ErrorView, AuthGuard, ...
    ...
  stores/
    rootStore.ts      # RootStore 组合
    storeContext.tsx  # Provider + useStores()
    rootStoreContext.ts
    singleton.ts      # RootStore 单例（供非 React 层使用）
    authStore.ts
    uiStore.ts
  services/
    http.ts           # Axios 实例与拦截器
    xxx.ts            # 各业务接口（games, leaderboard, user, levels, learning, ...）
  styles/
    variable.less     # 颜色/尺寸等主题变量（主色 #0064ff）
    global.less       # 全局样式重置与工具类
  types/
    index.ts, api.ts  # 领域模型与接口类型
  utils/
    rem.ts            # rem 根字号动态适配
    error.ts          # getErrorMessage 等
  assets/
  mocks/              # mock 数据与 handler（可选）
```

### 4.1 关键入口与职责

- **`src/main.tsx`**：挂载 RootStoreProvider、RouterProvider，引入全局样式，执行 setupRem()。
- **`src/app/router.tsx`**：createBrowserRouter 路由表，AuthGuard 包裹需登录路由。
- **`src/app/TabLayout.tsx`**：底部 Tab 壳，Outlet 渲染子路由，安全区占位。
- **`src/app/App.tsx`**：可选全局壳（MSW 启动、错误边界、Toaster 等）。

### 4.2 目录职责约定

- **app/**：应用级组装，不放具体业务逻辑。
- **pages/**：页面级，只组织布局与调用 store/service；异步请求建议 loading/error/空态三态。
- **components/**：可复用 UI，与业务弱耦合，移动端优先（点击区域/安全区）。
- **stores/**：MobX 状态层，避免在页面内直接写请求逻辑。
- **services/**：API 访问层，对上提供稳定函数签名。
- **styles/**：Less 与主题变量，颜色统一从 `variable.less` 引用（主色 #0064ff）。
- **types/**：领域模型与接口类型，避免散落在页面。

## 五、MobX 状态管理

### 5.1 Store 划分

- **authStore**：登录态、token、用户信息（含部门等），持久化到 localStorage。
- **uiStore**：全局 UI 状态（如当前场景/模块、侧栏等），按需扩展。

（若后续按领域扩展：userStore、gameStore、leaderboardStore、sessionStore 等可再拆。）

### 5.2 RootStore 与注入

- RootStore 组合各 store 实例；React 侧通过 Context 提供，页面/组件通过 `useStores()` 获取。
- 非 React 层（如 service 内需读 token）可使用 `stores/singleton.ts` 暴露的 rootStore。

### 5.3 数据流约定

- 页面触发 action → store 调用 service → 更新 observable → UI（observer）自动响应。
- 列表/统计等请求建议标准化：加载中、错误、空态三态，并统一使用 getErrorMessage 展示错误。

## 六、Less 样式与主题

### 6.1 变量文件（variable.less）

- `@color-primary`：主色 **#0064ff**，映射到 `--color-primary`、`--adm-color-primary`；半透明主色使用 `rgba(0,100,255,...)`。
- `@color-danger` / `@color-warn` / `@color-success`：语义色。
- `@color-text` / `@color-text-muted` / `@color-bg` / `@color-card` / `@color-line`。
- 阴影、线框、间距（`--space-*`，其中 `--space-2: 0.22rem`）、圆角（`--radius-*`，卡片统一使用 `--radius-card: 0.213rem` 即 8px）、字号（`--font-*`）等见 variable.less。
- 卡片圆角：全局卡片（含 .card、.adm-card、.adm-list）使用 `--radius-card`（8px）；大圆角按钮（.actionPill）图标与文字间距 `--space-1`。

### 6.2 主题与可扩展

- 默认主题：消防安全风格（对比度与警示色）。
- 深色模式：可后续增加 variable.dark.less 并在构建或运行时切换。

### 6.3 移动端适配

- 底部 Tab：处理 iOS safe-area inset。
- 点击区域：按钮/列表项满足移动端可点击尺寸。
- 列表性能：数据量大时再考虑虚拟列表（按需）。

### 6.4 个人主页（我的）样式约定

- **快捷入口**：flex + 百分比布局，一行固定 5 个（`flex: 0 0 calc((100% - 4 * var(--space-2)) / 5)`，`gap: var(--space-2)`）；图标 18px，入口名称 `var(--font-caption)`。
- **积分明细**：列表项主文案与数值使用 `var(--font-body)`，不大于卡片标题，保持层级清晰。

### 6.5 首页样式约定

- **上半部**：使用 `PersonalInfoCard` 展示个人信息卡片（头像首字、姓名、部门/基地、积分标签），下方接 `PersonalDashboard` 图表。
- **个人看板图表**：使用 @antv/f2 + @antv/f2-react；X 轴为最近 10 天日期，柱状图表示当日局数（主色 #0064ff）、折线图表示当日总积分（平滑曲线 shape="smooth"，颜色 --color-warn #fa8c16）；双 Y 轴（左侧局数、右侧积分，局数刻度 formatter 取整）；图例以 HTML 形式与标题「最近 10 天游戏记录」同一行靠右；图表主题与页面一致（坐标轴颜色、padding 等）；当前为 Mock 数据，后续可接真实成绩接口。
- **下半部**：场景提示行（当前场景 +「场景与关卡」按钮，actionPill 图标与文字 gap: var(--space-1)）之下使用「场景训练」标题与按模块分组的关卡卡片列表。
- **场景训练列表**：使用 `LevelGroup` + `LevelCard` 组合；列表容器为 flex + `gap: var(--space-2)`，卡片无 margin，仅靠 gap 控制间距；卡片圆角 `--radius-card`。
- **页面底部**：Page 组件 paddingBottom 含 tabbar 高度 + `var(--space-4)` + safe-area，避免滚动到底与 Tab 重合。

## 七、接口设计

统一响应格式（可先 mock）：

```json
{
  "code": 0,
  "data": { ... }
}
```

错误时可由后端返回 `code !== 0` 或 HTTP 4xx/5xx，前端通过 `getErrorMessage` 或解析 `response.data.error.message` 展示。

### 7.1 游戏与关卡

| 接口名称     | 请求方式 | 路径                     | 说明 |
|--------------|----------|--------------------------|------|
| 游戏/场景列表 | GET      | /api/.../scenes 或等价   | 首页模块与游戏列表 |
| 关卡列表     | GET      | /api/.../levels?module=  | 按模块拉取关卡 |
| 关卡详情     | GET      | /api/.../levels/:id      | 游戏首页/游戏内使用 |

### 7.2 用户与认证

| 接口名称     | 请求方式 | 路径           | 说明 |
|--------------|----------|----------------|------|
| 个人基础信息 | GET      | /api/me        | 个人主页（含 department） |
| 个人统计     | GET      | /api/me/stats  | 总积分、各游戏最佳等 |
| 积分流水/生命 | GET      | /api/...       | 积分明细、生命值等（按现有实现） |

### 7.3 排行榜

| 接口名称 | 请求方式 | 路径     | 参数示例 | 说明 |
|----------|----------|----------|----------|------|
| 排行榜   | GET      | /api/leaderboard | gameId, mode, scope, departmentId, page, pageSize | 支持按游戏/全局/部门筛选与分页 |

### 7.4 成绩与学习

| 接口名称     | 请求方式 | 路径           | 说明 |
|--------------|----------|----------------|------|
| 提交成绩     | POST     | /api/scores    | gameId, score, duration, difficulty, clientMeta |
| 学习分类/资料 | GET      | /api/learning/categories, /learning/materials | categoryId 可选 |
| 学习记录     | POST     | /api/learning/records | materialId, status |
| 关卡尝试/结算 | POST/GET | /api/.../attempts 等 | 按现有 levels/attempts 实现 |

（具体路径与参数以项目内 `services/` 与后端契约为准；错误码与前端展示约定可在联调时补充。）

## 十一、全站 UI 规范与已落地变更

### 11.1 基准策略

- **主容器**：所有一级、二级页面统一使用 `Page` 组件作为主容器，保证标题区、内容区、底部安全区一致。
- **区块标题外置**：列表/区块的标题放在卡片/列表容器外、上方，使用统一大标题样式（见下）。
- **大标题**：页面内区块标题统一使用 `sectionTitle` 类（`font-size: var(--font-title3)`，`color: var(--color-text)`，字重 600，与内容区间距 `var(--space-3)`）。
- **sectionCard / sectionCardList**：内容区块使用 `sectionCard` 包裹；若为列表，使用 `sectionCardList`（flex 布局、gap、无额外 margin）。
- **变量**：颜色、间距、圆角、字号均从 `variable.less` 或 CSS 变量读取，不写死数值；主色 `#0064ff`。
- **二级页**：统一顶部导航（返回 + 标题），无底部 Tab；Tab 仅在一级页展示。

### 11.2 全局样式与组件

- **variable.less**：主色、语义色、背景/卡片/分割线、间距（`--space-*`）、圆角（`--radius-card` 等）、字号（`--font-*`）已统一。
- **global.less**：`.sectionTitle`、`.sectionCard`、`.sectionCardList`、`.actionPill` 等已注入；Page 底部留白含 tabbar 高度与安全区。
- **Page 组件**：支持 `title`、`showBack`、`right`、`children`，二级页使用 `showBack` 展示返回。
- **BottomTab**：一级页底部 Tab，与路由一致；进入二级页后隐藏。

### 11.3 各页面变更汇总

- **首页**：主容器 Page；区块标题「最近 10 天游戏记录」「场景训练」使用 sectionTitle；个人看板与场景列表用 sectionCard/sectionCardList；场景与关卡入口为 actionPill + LevelGroup/LevelCard。
- **排行榜**：Page + sectionTitle + sectionCardList；列表项样式统一。
- **个人主页（我的）**：Page；区块标题外置；快捷入口、积分明细等用 sectionCard；个人信息区使用 PersonalInfoBlock（见下节）。
- **游戏首页 / 游戏内**：Page + showBack，无 Tab；内部区块同样遵循 sectionTitle + sectionCard。
- **关卡列表（levels）**：二级页；Page + showBack；分组列表用 sectionCardList + LevelCard。
- **学习中心、积分商城、订单列表等**：统一 Page、sectionTitle、sectionCard/sectionCardList；二级页 Tab 隐藏、顶部返回。

### 11.4 二级页与 Tab 规范

- 一级路由（如 `/home`、`/rank`、`/me`）：显示底部 Tab。
- 二级路由（如 `/game/:id`、`/levels`、`/level/:id/*`、`/store`、`/learning` 等）：不显示 Tab，顶部显示返回按钮；返回后恢复 Tab。

## 十二、设计策略：个人信息区

### 12.1 组件与结构

- **PersonalInfoBlock**：用于首页与「我的」页顶部的个人信息展示区块。
- **结构**：头像区（左侧，支持头像图或姓名首字 fallback）+ 右侧：姓名、部门/基地（可选一行）、积分/生命等摘要（标签或短文案）。
- **类名**：容器 `personalInfoBlock`，内部 `personalInfoBlock-avatar`、`personalInfoBlock-body`、`personalInfoBlock-meta` 等，便于覆盖样式。

### 12.2 使用场景

- **首页**：展示当前用户姓名、部门、基地、总积分/可用积分等，与个人看板图表衔接。
- **我的**：展示同一用户信息，可与积分明细、成就等区块区分层级（sectionTitle 外置）。

### 12.3 扩展说明

- 若需展示更多字段（如等级、徽章），在 `personalInfoBlock-body` 或 `personalInfoBlock-meta` 中扩展，保持主色与 variable.less 一致。

## 十三、设计策略：场景与关卡页

### 13.1 两段式结构

- **第一段**：分组/筛选区（如按模块、难度筛选），与路由或 store 中的当前场景/模块联动。
- **第二段**：游戏/关卡卡片列表，每个卡片包含：游戏图、标题、可选副标题（如完成状态、难度）。

### 13.2 游戏卡片规范

- 使用统一卡片组件（如 LevelCard）：圆角 `--radius-card`，封面图比例固定（如 16:9 或 4:3），标题使用 `--font-body` 或 `--font-title3`，副文案使用 `--font-caption`、`--color-text-muted`。
- 列表容器：flex 或 grid + gap（如 `var(--space-2)`），无额外 margin，符合 sectionCardList。

### 13.3 与当前实现的关系

- 关卡列表页（如 `/levels`）已按「分组 + 关卡卡片」实现；新游戏或新模块接入时，复用 LevelGroup + LevelCard 与现有 store/service，仅扩展数据与路由即可。
