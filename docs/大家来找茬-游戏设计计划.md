# 大家来找茬 — 游戏设计计划

## 一、玩法简介

「大家来找茬」是经典的**双图找差异**玩法：系统在**手机端**以**上下两图**展示两张高度相似的图片，玩家在限定时间或次数内**点击/标记出所有差异点**。每找对一处计为正确一步，点错可记为错误（可选限制错误次数或仅提示）。

**终端与布局**：仅支持**移动端**，不单独做桌面端适配。两图采用**上下排列**（上图 + 下图），便于竖屏滑动对比查看。

**学习场景结合（与现有项目一致）**：可围绕消防安全、隐患排查等主题设计「找茬图」——例如上下两图在消防通道、标识、器材摆放等细节上有若干处不同，既锻炼观察力又强化知识点。

**核心目标**：
- 观察与对比能力
- 可选：每处差异对应一个知识点（找对后展示简短说明）

## 二、接入方式（关卡 `game_type`）

与现有游戏一致，通过关卡 `game_type` 接入：

- 在 `src/types/api.ts` 的 `GameType` 中新增：`'spot-difference'`（或别名 `'find-diff'`）
- 关卡配置：`level.game_type = "spot-difference"`
- 路由与入口：`/level/:id/play` 由 `LevelPlay` 根据 `game_type` 调用 `renderGame('spot-difference', { level, onExit })`
- 在 `renderGame.tsx` 中增加分支，`lazy` 加载 `SpotDifferenceGame` 组件

**代码改动点**：
- `src/types/api.ts`：扩展 `GameType`
- `src/components/games/renderGame.tsx`：新增 case、lazy 引用
- 新建目录：`src/components/games/spot-difference/`（主组件、类型、题库/配置、样式）

## 三、关卡与题目数据结构

### 3.1 单关配置（SpotDifferenceLevelConfig）

建议与「分类大挑战」类似，首版采用**前端内置关卡配置**，后续可改为按 `level.id` / `module_id` 从后端拉取。

```ts
// 单处差异：用相对比例描述区域，便于不同分辨率下适配（移动端竖屏）
type DifferenceRegion = {
  id: string;                    // 唯一标识，用于 step_id 上报
  /** 上图（上方图片）上的区域，比例 [0,1]：左、上、宽、高 */
  top: { x: number; y: number; w: number; h: number };
  /** 下图（下方图片）上的区域（可与 top 相同，表示“两图该位置有差异”） */
  bottom: { x: number; y: number; w: number; h: number };
  /** 可选：找对后展示的知识点/说明 */
  knowledgePoint?: string;
  /** 是否关键差异（错误时是否记 key_error）一般找茬不区分，可省略 */
  isKey?: boolean;
};

type SpotDifferenceLevelConfig = {
  id: string;
  name: string;
  /** 上图 URL 或静态资源路径（展示在屏幕上方） */
  imageTop: string;
  /** 下图 URL 或静态资源路径（展示在屏幕下方） */
  imageBottom: string;
  /** 本关所有差异点（顺序可打乱展示，点击判定时按区域匹配） */
  differences: readonly DifferenceRegion[];
  /** 总限时（秒）；不填则不限时 */
  totalSeconds?: number;
  /** 允许的错误点击次数；超过可判失败或仅提示。不填则不限 */
  maxWrongClicks?: number;
  /** 是否开启“提示”：高亮下一处差异（可选，二期） */
  allowHint?: boolean;
};
```

说明：
- 区域用比例可做响应式：点击坐标转换为**当前点击的那张图**内的比例，与 `top`/`bottom` 比较，若落在某 `DifferenceRegion` 内且未找过则判对。
- 判定方式：点击位置落在某差异区域内 → 记为该差异已找到（step_ok）；点击不在任何未找过的差异内 → 记一次错误（step_error），可选 `maxWrongClicks` 判失败。

### 3.2 题目库（bank）与关卡映射

- 首版在 `spot-difference/bank.ts` 中维护若干 `SpotDifferenceLevelConfig`，用 `level.name` 或 `level.id` 做简单映射（与 classify-challenge 的 `pickDefaultLevelConfig` 类似）。
- 后续：由后端接口返回 `imageTop`、`imageBottom`、`differences` 等，前端只负责渲染与上报。

### 3.3 图片与差异资源

- 图片：可放 `spot-difference/assets/` 或使用 CDN URL。
- 差异区域数据：可由设计/运营在编辑器中框选生成（导出为 top/bottom 比例），或首版手写少量 demo 数据。

## 四、核心交互与 UI

### 4.1 布局（仅移动端、上下两图）

- **终端**：仅支持**手机端**，不单独做桌面端布局。
- **排版**：**上图 + 下图** 上下排列，整屏可**上下滑动**对照查看两张图；单张图片宽度撑满屏幕，高度按比例或最大高度限制，避免横拉。
- **顶部**：关卡名、进度（如「已找 2/5」）、剩余时间（若限时）、错误次数（若限制）。
- **中间**：上图（imageTop）+ 下图（imageBottom），中间可加一条分隔线或留白区分。
- **底部**：退出按钮；可选「提示」按钮（若 `allowHint`）。

### 4.2 点击判定

- 玩家在**上图或下图**上点击（触摸）。
- 将点击坐标转换为**相对当前被点击图片的比例 (x, y)**，检查是否落在某个「未找到」的差异区域（该图对应 `top` 或 `bottom`）内；判定阈值可设容差（如区域向外扩展 5% 仍算对）。
- 若命中：该差异标记为已找到，展示短暂高亮/勾选动画，并上报 `step_ok`；若配置了 `knowledgePoint` 可 Toast 或小浮层展示。
- 若未命中：上报 `step_error`，可选 Toast「再想想」；若启用 `maxWrongClicks` 则错误次数 +1，超限则本局失败。

### 4.3 完成与退出

- 当所有差异均被找出 → 自动结算为**通过**，跳转**通关页**（LevelPass，与现有流程一致）。
- 若限时到或错误次数超限 → 结算为**失败**，跳转**结算页**（Settlement）；大家来找茬失败时结算页展示「未找到的差异」列表，见 §10.2。
- 用户点击「退出」→ 视为 `aborted`，调用 `onExit()` 回到准备页（可选先弹确认框）。

## 五、attempt 上报与结算

与现有 attempt 体系保持一致：

- 进入游戏前：`LevelPrepare` 已创建 attempt，`attemptId` 通过路由 state 传入 `/level/:id/play`。
- 游戏中：
  - 每找对一处：`sendEvents(attemptId, [{ event_type: 'step_ok', step_id: difference.id, knowledge_point }])`
  - 每点错一次：`sendEvents(attemptId, [{ event_type: 'step_error', step_id: 'wrong_click', error_type: 'mis_touch' }])`（若后端支持）
- 结束时：
  - `settleAttempt(attemptId, { status: 'passed' | 'failed' | 'aborted', score, duration_ms, fail_reason?, error_count?, key_error_count? })`
  - 通过：`status: 'passed'`，可带 `score`（如按找全数 + 时间折算）、`duration_ms`。
  - 失败：`status: 'failed'`，`fail_reason`: `'timeout' | 'key_error' | 'other'`（错误过多用 `other`）。
  - 退出：`status: 'aborted'`，`fail_reason: 'manual_abort'`。
- 跳转：`navigate("/level/:id/settlement", { state: { attemptId } })`，与分类大挑战一致。

若当前 `AttemptEvent` 的 `step_id` 仅支持字符串，用 `difference.id` 即可；若需区分「错误点击」可单独一种 step_id（如 `wrong_click`）或复用现有 `error_type`。

## 六、技术实现要点

### 6.1 组件结构

- `SpotDifferenceGame.tsx`：主组件，接收 `GameRenderProps`（level, onExit），内部：
  - 从 bank 或 level 取 `SpotDifferenceLevelConfig`；
  - 状态：已找到的差异 id 集合、错误次数、开始时间、是否结束；
  - 渲染：Page + PageHeader + **上下双图**（可滚动容器）+ 每张图上的点击层（透明 overlay 或图片上绑 onClick）；
  - 计时器：若 `totalSeconds` 存在，倒计时，到 0 则自动失败并结算。
- `types.ts`：`DifferenceRegion`、`SpotDifferenceLevelConfig`、`SpotDifferenceRunSummary`（本地结算用）。
- `bank.ts`：内置 1～2 关 demo 配置（含图片路径与 differences 数组）。
- `utils.ts`：坐标转比例、点击是否落在某区域内的判定函数。
- `SpotDifferenceGame.less`：布局（上下双图、可滚动）、进度条、按钮样式；按移动端竖屏设计，不做桌面端媒体查询。

### 6.2 坐标与区域判定

- 图片用 `<img>` 或背景图，外层用 ref 取 clientWidth/clientHeight 和 getBoundingClientRect()。
- 点击时用 clientX/clientY 转为相对图片左上角的比例 (x, y)，x = (clientX - rect.left) / rect.width，y 同理。
- 判断 (x, y) 是否在某个 `DifferenceRegion.top` 或 `bottom` 内（根据当前点击的是上图还是下图）：  
  `x >= region.x && x <= region.x + region.w && y >= region.y && y <= region.y + region.h`，可加小容差。

### 6.3 性能与体验

- 图片可预加载，避免进入关卡后白屏。
- 差异区域可先不画在 DOM 上（仅逻辑判定）；若要做「找对后高亮」，可用绝对定位的 div 或 svg 覆盖在对应比例位置，避免整图重绘。

### 6.4 与现有项目一致

- 使用 `Page`、`PageHeader`、`Button`、`Toast`/`Modal`（antd-mobile）。
- 风格与 `ClassifyChallengeGame`、`LinkMatchGame` 等保持一致（字体、间距、圆角、主色）。

## 七、分阶段实现建议

### 第一阶段（MVP）

1. 类型与路由：`GameType` 增加 `'spot-difference'`，`renderGame` 增加分支并 lazy 加载。
2. 数据结构：定义 `DifferenceRegion`、`SpotDifferenceLevelConfig`，在 bank 中写 1 关 demo（2 张图 + 3～5 处差异）。
3. 主组件：双图展示 + 点击判定（比例计算 + 区域内判定）+ 已找差异高亮/标记。
4. 进度与结束：顶部显示「已找 x/总数」；找全即通过，调用 `settleAttempt` 并跳转结算页。
5. 退出：顶部返回 + 退出确认，调用 `onExit()`。

可不做或从简：限时、错误次数上限、attempt 事件上报（可先写死通过/失败，再接 sendEvents）。

### 第二阶段（完整规则与埋点）

1. 限时：`totalSeconds` 倒计时，到点自动失败并结算。
2. 错误次数：`maxWrongClicks`，点错超限即失败。
3. attempt 全量接入：找对/点错都 `sendEvents`，结束时 `settleAttempt` 带 status、score、duration_ms、fail_reason、error_count。
4. 结算页：与现有 LevelPass/LevelFail 一致，展示得分、耗时、可复盘（若后端支持 review）。

### 第三阶段（增强）

1. 知识点：每处差异配置 `knowledgePoint`，找对后 Toast 或小浮层展示。
2. 提示：`allowHint` 为 true 时显示「提示」按钮，点击后高亮下一处未找差异（可限制提示次数）。
3. 多关卡：bank 多关，按 level.id/name 映射；或接入后端关卡配置。

- 图片：可用两张相同图 + 少量差异（用图片编辑软件做出 3～5 处不同），或使用免费「找茬」素材。

## 九、总结

| 项目         | 说明 |
|--------------|------|
| 终端         | 仅移动端，不做桌面端 |
| 游戏类型     | `spot-difference`，双图找差异 |
| 布局         | 上下两图（上图 + 下图），可上下滑动对照 |
| 关卡数据     | 上图、下图 URL（imageTop/imageBottom）+ 差异区域列表（top/bottom 比例） |
| 交互         | 点击/触摸上图或下图，命中差异即判对 |
| 胜利条件     | 找全所有差异（可选限时、错误次数） |
| 与现有架构   | 复用 Level、Attempt、renderGame、结算跳转 |
| 实现顺序     | MVP 上下双图+点击判定 → 限时/错误+埋点 → 知识点/提示/多关 |

按上述计划可实现与现有「分类大挑战」「连连看」等一致的接入方式与体验，并便于后续扩展为后端配置与更多关卡。

## 十、实现与变更说明（与当前代码一致）

以下为当前实现中的功能与设计文档的对应及变更说明，便于后续维护与扩展。

### 10.1 通关页与结算页统一布局

- **LevelResultLayout**：通关页（LevelPass）与结算页（Settlement）共用同一布局组件。
- **顶部**：大标题（如「挑战成功」「结算完成」）+ 可选描述，使用 `PageHeader`，且 **Header 吸顶**（`page-header-sticky`），随页面滚动时固定在顶部不被遮挡。
- **底部**：吸底固定，「返回列表」「重新游戏」两个按钮；不再使用向上阴影，避免遮挡内容。

### 10.2 大家来找茬失败时的结算页

- **大家来找茬**（`game_type === 'spot-difference'`）**未通过**时进入结算页，展示 **「未找到的差异」** 列表（两图中尚未找出的差异项），而非通用「错误题目」时间线。
- 未找到的差异根据复盘 `timeline` 中 `result === 'ok'` 的 `step` 与关卡配置 `differences` 计算得出；列表项展示 `knowledgePoint` 或「差异 N」。

### 10.3 通关页知识卡片展示方式

- **连连看**（link-match/llk）：保留 **左右滑动** Swiper 展示多张带图知识卡片。
- **大家来找茬、分类大挑战、步骤类**：知识卡片改为 **垂直列表** 展示，不再左右滑动，避免与页面上下滚动混淆，并减轻阴影遮挡感。

### 10.4 大家来找茬游戏内

- 上下两图之间间距已缩小（`spot-difference__scroll` 的 `gap` 与分隔线 `margin` 调小）。
- 图片加载失败时展示占位文案并 Toast 提示；坐标判定对 `rect` 宽高为 0 做了防护；退出确认时使用 ref 读取最新已找数量与错误次数，避免闭包陈旧。
