# 分类大挑战（Swipe 归类）

## 一、玩法简介

“分类大挑战”是一种**左右滑动归类**的学习型小游戏：系统逐题给出“场景/物品”卡片，玩家通过**左滑 / 右滑**把卡片归到对应类别，并立即获得“对/错 + 解释 + 知识点”的反馈。

首版主题为**消防安全**，题库覆盖：
- 灭火器选型（能不能用、为什么）
- 火灾类型识别（A 类固体 / B 类液体）
- 现场处置判断（应该做 / 不应该做）

## 二、接入方式（关卡 `game_type`）

只要关卡配置满足：
- `level.game_type = "classify-challenge"`

则在 `/level/:id/play` 页面会自动走游戏容器渲染（项目现状：`LevelPlay` 已按 `game_type` 调用 `renderGame`）。

对应代码位置：
- 游戏类型：`src/types/api.ts`（`GameType` 增加了 `classify-challenge`）
- 渲染入口：`src/components/games/renderGame.tsx`（lazy 动态加载）
- 游戏实现：`src/components/games/classify-challenge/ClassifyChallengeGame.tsx`

## 三、题库与关卡配置

首版题库为**内置静态数据**：
- `src/components/games/classify-challenge/bank.ts`

每关结构（简化说明）：
- `categories`: 固定 2 个（left/right），匹配 swipe
- `questions`: 题目列表（含 `correctCategoryId`、`explain`、`knowledgePoint`、`isKey`）
- `takeCount`: 本关抽题数量（默认用全量）
- `perQuestionSeconds`: 单题限时（秒），到点自动判定为超时错误
- `maxErrors` / `maxKeyErrors`: 错误阈值，超过即失败

如果后续要与后端对齐，推荐：
- 用 `level.id` 或 `module_id` 映射到后端关卡配置
- 由后端下发 categories/questions 与阈值，前端只负责渲染与上报

## 四、attempt 上报与结算（已接入）

当从准备页开始挑战时，`LevelPrepare` 会创建 attempt 并把 `attemptId` 通过路由 state 传入：
- `navigate("/level/:id/play", { state: { attemptId } })`

“分类大挑战”在 `attemptId` 存在时会：
- 记录每题事件（正确/错误、知识点、关键错误、超时等）
- 游戏结束时调用：
  - `sendEvents(attemptId, events)`
  - `settleAttempt(attemptId, payload)`
- 并跳转结算页：
  - `navigate("/level/:id/settlement", { state: { attemptId } })`

注意：
- 当前 attempt 的 `fail_reason` 使用后端已支持的枚举：`timeout | key_error | manual_abort | other`
- “错误过多”在上报时会映射为 `other`（避免与后端枚举不一致）

## 五、交互与可用性（手势 + 兜底）

- **移动端**：拖拽卡片，左/右滑动超过阈值即提交答案
- **桌面端**：提供两个按钮（左类 / 右类）作为输入兜底
- **误触控制**：纵向滚动优先，避免上下滚动时误触滑动判定
