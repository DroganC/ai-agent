# 前端代码审查报告

## 审查概要

- **审查范围**：`src/` 下路由、页面、服务、游戏组件、配置与工具
- **审查重点**：正确性、边界条件、React 使用方式、可维护性
- **整体评价**：结构清晰，路由与配置收敛合理；发现并修复若干边界与生命周期问题。

## 已修复问题

### 1. 生产代码中的 console.log（renderGame.tsx）

- **位置**：`src/components/games/renderGame.tsx`
- **问题**：`renderGame` 内保留 `console.log('renderGame', type, props)`，会在每次渲染游戏时打日志。
- **处理**：已删除该行。

---

### 2. 无效 levelId 时 Loading 不结束（LevelPrepare）

- **位置**：`src/pages/LevelPrepare/index.tsx` 的 `load` 回调
- **问题**：当 `levelId` 无效（如 `id` 为 undefined 导致 `Number(id)` 为 NaN）时，`load()` 直接 return，未调用 `setLoading(false)`，页面会一直处于 Loading。
- **风险**：直接访问 `/level/undefined/prepare` 或错误 id 时白屏。
- **处理**：在 `!Number.isFinite(levelId)` 分支中增加 `setLoading(false)` 与 `setError('无效的关卡 ID')`。

---

### 3. 重定向时 id 可能为 undefined（LevelPlay）

- **位置**：`src/pages/LevelPlay/index.tsx` 中“无 game_type 且无 attemptId 时回准备页”的 useEffect
- **问题**：未判断 `id` 是否存在就执行 `navigate(\`/level/${id}/prepare\`)`，若 `id` 为 undefined 会跳转到 `/level/undefined/prepare`。
- **处理**：在 effect 内增加 `if (id == null) return;` 再执行 navigate。

---

### 4. 缺少 attemptId 时与 id 缺失时的跳转（Settlement）

- **位置**：`src/pages/Settlement/index.tsx`
- **问题**：`goPrepare` 未判断 `id`，可能跳到 `/level/undefined/prepare`；缺少 attemptId 时的 `onRetry` 也未区分 id 是否存在。
- **处理**：`goPrepare` 中若 `id != null` 跳转关卡准备页，否则跳 `/levels`；缺少 attemptId 的 ErrorView 的 `onRetry` 同样按是否有 id 分别跳转；「再来一次」按钮改为调用 `goPrepare` 以复用上述逻辑。

---

### 5. 登录回调在卸载后仍执行 setState/navigate（LoginCallback）

- **位置**：`src/pages/LoginCallback/index.tsx`
- **问题**：`exchangeComeCode` 为异步，若组件在请求完成前卸载（如用户离开页面），仍会执行 `navigate()` 或 `setError()`，可能触发“在已卸载组件上更新状态”的警告或异常。
- **处理**：使用 `useRef` 维护 `isMountedRef`，在 effect 清理函数中设为 false，在 then/catch 中仅当 `isMountedRef.current` 为 true 时再调用 `navigate` 或 `setError`。

---

### 6. List 使用 index 作为 key（Settlement）

- **位置**：`src/pages/Settlement/index.tsx` 中错误时间线 List
- **问题**：使用 `key={idx}` 在列表顺序或条目不稳定时不利于 React 复用与更新。
- **处理**：改为 `key={\`${item.ts}-${idx}\`}`，在保留顺序信息的同时减少 key 冲突。

---

## 建议关注（未改代码）

### 1. 列表 key 的长期方案

- **位置**：多处 `.map(..., idx) => ... key={idx}`
- **建议**：若后端能为时间线等条目提供稳定唯一 id，优先使用 `item.id` 或 `item.ts + item.step` 等作为 key。

### 2. API 错误信息展示

- **位置**：`src/utils/error.ts` 的 `getErrorMessage`
- **说明**：当前对 Axios 错误主要用 `error.message`（如 "Request failed with status code 401"），未解析 `response.data.error.message`。
- **建议**：若希望展示后端返回的文案，可在拦截器或调用处先用 `getAxiosApiError(error)` 再传 `message` 给 UI，或扩展 `getErrorMessage` 识别 AxiosError 并读取 body。

### 3. 游戏内页双入口与 attemptId

- **说明**：从 `/game/:gameId/play` 进入的 GamePlay 不携带 attemptId，游戏内结算/跳转行为与从 LevelPrepare 进入不一致（见此前《前端路由审查》）。
- **建议**：按路由审查结论统一入口或在 GamePlay 侧补建 attempt 并传入 attemptId。
